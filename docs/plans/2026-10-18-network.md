## 1. What the card was

§29 ended with three policies that had no caller, because the VM boots with no NIC:

| policy | where | what it needed |
|---|---|---|
| the egress deny list + the resolver's half of it | `src/vmd/egress.zig` (8 tests) | something that dials, and a DNS channel with the same policy |
| the preview origin's rules | `src/http_handlers/preview_origin.zig` (9 tests) | a proxy that forwards a host request to a guest port |
| — | — | an in-guest `resolv.conf` writer and a forwarding resolver |
| — | — | the first CSRF/`Origin` check this server has ever had |

§11.4 named the missing prerequisite as an **opt-in privileged tap helper** (CAP_NET_ADMIN
only, never the server). This card supplies the callers, the resolver, the preview proxy,
the `Origin` wiring, and the tap helper — and it prefers the vsock-only path everywhere the
vsock-only path can work, because **both proxies and the preview need no NIC at all**.

## 2. The shape

Two directions, one transport. Firecracker's vsock is *hybrid*: the host dials the guest by
connecting to `<uds_path>` and sending `CONNECT <port>\n`, and the guest dials the host by
connecting to CID 2 on a port, which Firecracker turns into a connection to the host's
listener at **`<uds_path>_<PORT>`**. That convention was prose in §19/Appendix A before this
card; it is now measured (see §6).

```
             guest                                    host
  ┌──────────────────────────────┐        ┌────────────────────────────────────────┐
  │ tenant: curl/npm/git         │        │ pabrik-vmd                             │
  │   http_proxy=127.0.0.1:3128 ─┼─┐      │                                        │
  │   resolv.conf → 127.0.0.1:53 │ │      │  vsock.sock_5001  ← CONNECT-line + raw │
  │                              │ │      │     allowlist, resolve-then-connect,   │
  │ pabrik-vm-netd (PID 1 spawns)│ │      │     169.254/16 + loopback + host ports │
  │   :3128  HTTP proxy          ┼─┼──────┼─→  vsock.sock_5002  ← framed DNS       │
  │   :53    UDP resolver        ┤ │vsock │     queryName + answerDenied + 4 KiB   │
  └──────────────────────────────┘ │CID 2 │                                        │
                                   │      │  <uds_path>  → CONNECT 5000 → agent    │
  guest dev server 127.0.0.1:3000 ←┼──────┼── port.forward (a request/response op)  │
                                   │      │  ← the server's /api/preview route     │
                                   └──────┘  (preview_origin strips and rebuilds)  │
```

The **tap** is the other path and it is opt-in: a separate `pabrik-vm-tap` binary that holds
CAP_NET_ADMIN and creates the device; the server never runs it and never holds the
capability. Nothing in the vsock path needs it (§7 says exactly what is unverified).

## 4. The decisions, and why

1. **Vsock-only is the default; the tap is opt-in.** §11.4 already said the tap mode is a
   separate CAP_NET_ADMIN helper. Making it *the* path would have meant every deployment
   needs privilege, to buy only raw sockets (ping, mDNS). The two proxies need no NIC.
2. **The host resolves, and dials the literal it checked.** `resolveAndDial` walks the A
   records, refuses the whole dial if *any* answer is one `egress.decide` denies, and then
   connects to the first allowed address by value. A name cannot rebind between the check
   and the dial, because there is no second resolution.
3. **The resolver is the same channel with the same policy.** A guest query is forwarded
   verbatim only after `queryName` accepts it (one question, a standard query, ≥2 labels,
   ≤253 bytes); the answer is capped at `egress.resolver_response_cap`; every A/AAAA in it
   is classified, and one denied record turns the answer into a refusal. The guest's
   resolver turns a refusal into SERVFAIL, so a denied name is a failed lookup and not a
   silence.
4. **The workspace and the port list are the daemon's, never the wire's.** The proxy's
   workspace is the *directory the listener was bound for* (`workspaceOf`), so an allowlist
   cannot be chosen by a guest; `preview.ports` is read by the daemon, and a port that is
   not in it is refused with `port not declared`. An absent `egress.allow` means the web's
   own ports (80/443) and nothing else; an absent `preview.ports` means nothing is published.
5. **A malformed allowlist fails closed**: `Allowlist.parse` refuses the file rather than
   falling back to the permissive default, so a typo narrows egress instead of widening it.
6. **The preview proxy rebuilds the response rather than relaying it.** The guest's
   `Set-Cookie` never crosses back to the browser, hop-by-hop headers are dropped, CSP and
   `nosniff` are always set, and an active document is an `attachment` **on the app origin**
   (`previewDisposition`). It renders inline only when the request arrived on the
   workspace's own preview host, which needs the wildcard-DNS deployment and
   `PABRIK_PREVIEW_BASE`.
7. **The engine's own pre-gate is the `Origin` check**, because the framework already
   implements it (`security.preGateCheck`: state-changing method + foreign `Origin` → 403)
   and pabrik had simply never switched it on. A second middleware would have broken the
   route-table contract test (exactly one middleware per route); this does not.

## 5. The three hard rules, and the test that fails if the rule is removed

| rule (§5) | unit test | live |
|---|---|---|
| the guest never reaches `127.0.0.1:8081` or any host listener | `egress_proxy`: "a dial to a port this host listens on is refused whatever address carries it"; `egress.zig`'s own `decide` test | **yes** — the guest's own `wget` got `403 Forbidden` from the host's proxy, and `egress.log` says `outcome=host listener` |
| cookies never reach a tenant dev server | `preview_proxy`: "the app's credentials never reach the tenant's dev server" (Cookie, Authorization, Proxy-Authorization, X-Api-Key all absent from the bytes) | not applicable (the preview path is host-side) |
| a tenant `.html`/`.svg` never renders inline on the app origin | `preview_proxy`: "a tenant document is an attachment on the app origin and renders only on its own" | not applicable |
| DNS is not a way around the proxy | `egress_proxy`: "an answer that points inside the host fails the lookup", "a v6 answer inside the host is denied in its own family", "the resolver refuses a query it cannot read as a name" | **yes** — the guest resolved `example.com` through the host and the audit log has the `dns=` line |

## 6. Verification

```
zig build                                  exit 0   (server, agent, probe, netd, tap, vmd — all compile)
zig build vmd                              exit 0
zig build test:vmd                         exit 0   (includes egress_proxy, proxy_rpc, tap)
zig build test:shard:0..5,7                exit 0

FC_BIN=... scripts/vm-guest-smoke.sh       exit 0
FC_BIN=... scripts/vmd-daemon-smoke.sh     exit 0
scripts/vm-net-smoke.sh                    PASS  (below)
```

`scripts/vm-net-smoke.sh` boots a microVM through `pabrik-vmd` (128 MiB tier-`base` image,
no root, no tap) and asserts, in order:

1. the image ships `/usr/bin/pabrik-vm-netd` (read back with `debugfs`, no mount);
2. the guest's workload is uid 1000, `/etc/resolv.conf` says `nameserver 127.0.0.1`, and the
   serial log says `netd started`, `lo up`, `proxy listening on 127.0.0.1:3128`,
   `dns listening on 127.0.0.1:53`;
3. `/sys/class/net/lo/flags` is `0x9` (UP|LOOPBACK) inside the guest;
4. **a dial to `http://127.0.0.1:8081/health`** through the proxy → the guest sees
   `HTTP/1.1 403 Forbidden`, and `<workspace>/egress.log` has `outcome=host listener`;
5. a dial to `http://not.declared.example/` → refused *before any resolution*
   (`outcome=not declared`);
6. a dial to a declared host (`example.com 80`) → the real page comes back through the
   proxy, and the audit line records the resolved address (`outcome=allowed addr=104.20.23.154`);
7. `nslookup example.com 127.0.0.1` inside the guest → a real `A` answer, over vsock, through
   the host's resolver proxy;
8. the preview tunnel: `proxy.exchange` on the daemon's socket → `port.forward` in the guest
   → a `nc` server on the guest's `127.0.0.1:3000` → `HTTP/1.1 200 OK` + the body;
9. the same exchange against a port the workspace did **not** declare → `port not declared`.

Verified live, therefore: Firecracker's guest-initiated `<uds>_<PORT>` convention; the
handshake; resolve-then-connect against the real internet; the DNS proxy; the guest op; the
daemon's port allowlist. Not verified live: the preview *route* (needs the `pabrik` server
and a browser), the tap (`CAP_NET_ADMIN`), and anything about a second concurrent guest op.

## 7. What this does NOT do (stated, not implied)

- **The tap path has never run.** This box has no passwordless sudo, so `TUNSETIFF` and the
  `ip tuntap` steps are unexecuted. What *is* covered: the CAP_NET_ADMIN parse of
  `/proc/self/status`, the tap-name validation, the refusal when the capability is missing,
  and the pure builders (`nicConfig`, `bootIpHint`, `planText`). `pabrik-vm-tap --name X`
  prints the whole plan without CAP_NET_ADMIN and exits 1. The daemon does **not** create a
  NIC and `vm_client.boot` does not PUT `/network-interfaces`; that stays opt-in.
- **No CSRF token.** The `Origin` allowlist is wired (the engine's pre-gate); the
  synchronizer-token half of §11.2 is not, and `preview_origin.session_cookie_attributes`
  is still policy-with-tests only — turning `Secure` on for a plain-`http` deployment would
  break the session cookie this box uses.
- **The guest agent's frame loop is serial** (unchanged by this card). A long `exec` holds
  the one vsock connection, so a preview exchange waits behind it, and the reconciler's
  readiness probe can see the workspace as `starting` while one runs. The smoke works around
  it the way a user would: the guest's test server is started with `spawn` (detached), not
  `exec`. Fixing this properly means more connection threads in the agent, which is its own
  card.
- **The preview route is path-based** (`/api/preview?workspace_id=..&port=..&path=..`),
  because the router has no wildcard segment and no pre-router hook to intercept a
  `Host`-based request. The hosted form (`ws-<id>.preview.example.net`, its own registrable
  domain, where a tenant page renders inline) needs wildcard DNS, a cert, and either a
  wildcard route or the engine's static-dir hook; `PABRIK_PREVIEW_BASE` is read and
  `previewHostFor` is wired, so the deployment is one route away.
- **`accept` is unbounded**: the proxy spawns a thread per connection with no cap, exactly
  like the daemon's own control socket. A guest can open many connections; the ceiling is
  the host's fd limit, not a number this code chose.
- **UDP is not proxied** (only DNS-over-vsock is), and `git+ssh` is still unsupported, both
  as §11.4 already said.
- **`PABRIK_EGRESS_DENY_PORTS` defaults to `8081` alone.** Only the operator knows what else
  listens on the host; the resolver/DNS path is covered by the address table instead.

## 8. Traps that cost time on this card

- **A listener allocated from the request arena dies with the request.** `Manager.ensure`
  was called with the *per-connection arena*; the accept thread it started then read freed
  memory and the daemon SIGSEGV'd on the guest's first dial (found by the live smoke, not by
  a unit test). The listeners now come from `Manager.allocator` (the daemon's gpa). Anything
  a spawned thread can outlive must never be allocated from an arena.
- **`std.process.argsAlloc` is gone in Zig 0.16.** A `pub fn main()` that reads argv must
  take `init: std.process.Init` and walk `init.minimal.args` through
  `std.process.Args.Iterator`.
- **`inline for` + `catch continue` is "comptime control flow inside a runtime block".** A
  `for` over a comptime-known array is what is wanted; `inline for` only type-checked until
  the function was actually referenced — which is why `zig build test:vmd` was green while
  `zig build vmd` failed.
- **`var x = struct { ... }();` is not a value.** Module-level anonymous-struct state is
  `var x = struct { ... }{ };`.
- **`linux.recv` does not exist**; it is `linux.recvfrom(fd, buf, len, 0, null, null)`.
- **A `bool`-returning call used as a statement must be `_ =`.**
- **The guest forwarder had two real bugs that only a live VM could show**: it wrote the
  rewritten request back to the *client* instead of into the tunnel, and it dropped the
  request's header lines when the client used absolute-form (`GET http://host/path`) — the
  origin then waited forever. Both were found by the smoke's public GET, in a file that
  compiled and whose pure helpers all passed. Reviewing generated code is not verification.
- **The stray-`firecracker`/`pkill -f` trap**: `pkill -f '<pattern>'` matches the shell
  running it, so a cleanup command kills its own shell (use `pgrep -fa` first, or a bracket
  class in the pattern).

## 9. How to run it

```bash
cd <worktree>
zig build vm -Doptimize=ReleaseSmall      # agent, probe, netd, tap
zig build vmd -Doptimize=ReleaseSafe      # pabrik-vmd
FC_BIN=$HOME/firecracker-demo/firecracker scripts/vm-net-smoke.sh
FC_BIN=$HOME/firecracker-demo/firecracker scripts/vm-guest-smoke.sh
FC_BIN=$HOME/firecracker-demo/firecracker scripts/vmd-daemon-smoke.sh
```

Per workspace, on the host:

```
<root>/workspaces/<id>/egress.allow    # "<host-or-pattern> <port|any>" per line; absent → 80,443
<root>/workspaces/<id>/preview.ports   # one port per line; absent → nothing is reachable
<root>/workspaces/<id>/egress.log      # append-only audit: ts= workspace= host= port= outcome= addr=
```

Env: `PABRIK_EGRESS_DENY_PORTS` (host listener ports refused to every workspace),
`PABRIK_ALLOWED_ORIGINS` (extra origins the server serves, for the engine's pre-gate),
`PABRIK_PREVIEW_BASE` (the preview base domain).
