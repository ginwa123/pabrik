Projects and Documents, redrawn

Nineteen projects of four kinds share one 280px column, every row is the same row, the number on the right is a page size rather than a count, and the first document sits 608 pixels down. Left is the rail today. Right is the rail I would build.

What changed

19 of 19 projects, 3 of 3 documents

  1. 1

    The arrow goes, and a bar in the gutter takes its place

    Twelve boards, two agents, four routines and one design page render as the same chevron and name. The chevron is identical on all nineteen rows and only says "this row opens", which every row does, so it earns nothing. A 3px bar flush to the rail's left edge, one colour per kind, answers the question the row actually raises: what am I opening. The filter chips carry the same bar, so the legend teaches itself. If you want a mark back, the switcher under the redrawn rail shows a thin chevron, a plus and a caret on the same nineteen rows.

  2. 2

    Search, because nineteen rows is past scanning

    There is no search in the rail today; it was removed on purpose and pinned by a spec. One field above the sections filters projects and documents together, so position stops mattering and the 608px to Documents stops being a problem.

  3. 3

    The trailing number becomes state, not a count

    item.tasks.length counts the tasks the sidebar has paged in, not the project's total: pabrik_saas reads 20 because 20 were loaded. The slot keeps the one honest thing it can show, running and its elapsed time, and the count moves into the expanded block where it can be a real total.

  4. 4

    A new folder is named before it exists

    Three of the four folders in the database are called "New folder" with zero children, because the create writes that literal string and then opens a rename field you can click away from. Create it in rename mode, and an empty name deletes the row instead of keeping it.

  5. 5

    Delete leaves the row at rest

    The cross sits at opacity .55 on every folder row and deletes the folder and its children with no confirm. It moves into a hover menu, and the delete asks first.

  6. 6

    Documents get a time, not a zero

    A folder's child count is useful; a document's is always zero. The trailing slot shows when it was last edited, which is the only thing that helps you pick between two documents.

  7. 7

    The mark is yours to set

    One glyph per project, tinted by its kind, so the two marks carry different things: the bar says what kind of thing it is, the glyph says which one. It costs one nullable icon column on workspace_items, one more optional field in workspace_items_update.zig (the handler already takes item_type, path and name with the same presence semantics), one line in the API type, and a picker in the row menu. No new endpoint.

  8. 8

    Still open: a document cannot be found from its project

    Documents are workspace-scoped by design, so the note about kabelweb lives in a section that knows nothing about kabelweb. The fix is one nullable project_id and a Documents child row inside the expanded project. It is a migration, so it is not in this drawing.

Every number here was read from ~/.config/pabrik/agent.db read-only or from the shipped components: 19 items in the active workspace (12 kanban, 2 agent, 4 routine, 1 design), 2 documents both empty, 4 folders of which 3 are "New folder" with 0 children, 8 item_type='folder' rows the UI cannot create. Row height 32px, rail 280px, both from style.css. Two inspector findings are defended rather than fixed: still-page, because a spec document that animates itself would fake the motion it describes, and no-footage, because an internal rail has no clip to show.
