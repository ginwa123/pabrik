Routine runs: a real chat per fire

A routine fires, the pill says Success, and there is nothing to open. This is the design and the wireframe for giving every fire a run, its own chat session, and a place in the list of what is running now.

Why no chat exists

Firing takes a shortcut around the only funnel that creates a session. A chat send goes through App.emit_run_agent and then insert_worker. The fire emits the run-params event itself, one layer below both.

The run is a chat, and the chat has a run

Every fire gets a fresh session id and a row in a new routine_runs table whose session_id is that session. The session is inserted by us before the agent starts, stamped with the workspace and the routine's directory, so the run is in the sidebar while the first token is still streaming.

States. A failure is never an empty list and never a green pill. That single mistake, an errored run reporting success, is what makes a routine silently useless today.

The data model: no new table

A run is a chat session. Four columns on sessions carry the three things a session cannot infer, plus the error text the product throws away today. No new table, and nothing added to workspace_item_tasks, which is referenced by roughly 120 files and would put every run in the item's task list, the workspace counts and the agent's kanban tool.

-- Migration 125. One guarded addColumnIfMissing each, so a replay is a no-op.
ALTER TABLE sessions ADD COLUMN routine_id  TEXT NOT NULL DEFAULT '';  -- '' = an ordinary chat
ALTER TABLE sessions ADD COLUMN run_trigger TEXT NOT NULL DEFAULT '';  -- 'schedule' | 'manual'
ALTER TABLE sessions ADD COLUMN run_due_at  TEXT NOT NULL DEFAULT '';  -- the scheduled slot; '' for manual
ALTER TABLE sessions ADD COLUMN run_error   TEXT NOT NULL DEFAULT '';  -- why it failed, if it did

CREATE INDEX IF NOT EXISTS idx_sessions_routine ON sessions(routine_id, created_at DESC);

State is derived, never stored: a live worker row means running, last_finish_reason is stop or awaiting_user, sessions.status is cancelled, and no worker with no stop is a failure with run_error in hand. One predicate keeps runs out of the chat list, beside the one that already hides sub-agent sessions. Retention is deleting the session, which is a thing you already understand.

Order matters. Inserting the session ourselves is what lets it carry the workspace, and because that insert is ON CONFLICT DO NOTHING with the broadcast gated on db.changes() > 0, insert_worker stays a silent no-op afterwards: one broadcast, one sidebar row, no fight.

Decisions worth re-reading before the build

  1. The run is a session, not a table. This document's first revision added a routine_runs table. Every field it held was either already on the session or derivable from the worker row and last_finish_reason, so it is gone: four columns instead.
  2. Runs are still not workspace_item_tasks rows. They follow that table's id convention, but no query in the repo filters task_type, so a run row would surface as a task in the item's list, the workspace counts, run-all-agents and the agent's kanban tool, and there is no way to prune it without deleting something the user can see.
  3. The overlap guard stays claimForRun. last_status stops being a reported outcome and becomes the lock it already was; each run's state is derived per session instead of stored once.
  4. workspace_routines shrinks but stays. Its description duplicates agent_configs.description, last_run_at and last_error are derivable, and id equals workspace_item_id: thirteen columns to seven, in a migration of its own. Cron state has no other home here. §11 of the design shows the table disappearing into agent_configs, which already holds the routine's description, knowledge, tools and prompts.
  5. Scheduling arithmetic is untouched. Next fire is still computed from completion time. Changing that changes behaviour for every existing routine and deserves its own proof.
  6. Routines still do not set is_auto_retry_until_stop. A routine that retries itself until it stops is an unattended loop, which is exactly what that flag is not for.
