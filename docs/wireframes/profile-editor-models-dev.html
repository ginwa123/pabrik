Decisions to confirm

D1 — where the catalog lives

Recommend: runtime fetch + on-disk cache, backend-owned (one module, mirroring session_llm_config.zig's "one owner" rule). Alternatives: a 2.3 MB snapshot in git (rots, unreviewable diffs), or frontend-only fetch() (the server-side compaction bug survives).

D2 — when we refresh

Recommend: an explicit "Refresh catalog" button with a stale badge, never at boot — CI stays hermetic and the app never phones home unasked.

D3 — the orphaned global defaults

Recommend: one small "Compaction" block in Settings → General (threshold %, optional forced window). That is the single global home the fact line's compacts at 800k inherits from. Alternative: delete the cascade steps as dead UI — but workspace overlays and hand-edited configs use them.

D4 — model entry stays a combobox, not a select

Recommend: free text + catalog search. A strict dropdown breaks self-hosted endpoints and your opencode.ai/zen URL, which is not what the catalog says.

D5 — output cap and price on the fact line

Recommend: price yes, output cap no — the cap changes nothing today (nothing reads it), and the fact line is worth keeping to four tokens. Add a real max_output_tokens field only if you want Agent.maxTokens to stop being 4096.

D6 — workspace scope

Recommend: one machine-wide catalog cache — model metadata, not user data.

What does not change

  • The wire format. max_capacity_tokens / compaction_threshold_percent / thinking_budget_tokens stay number | null. An empty field must serialize to null, never "" (an empty slice binds as SQL NULL here).
  • No config migration. An existing config.json is byte-identical; only resolved values differ — correctly, for non-MiniMax models.
  • The catalog never writes into a profile. It supplies defaults at the resolution points the backend already has, so one refresh corrects every profile at once.

Risks

  • Offline. No cache ⇒ today's 200k built-in. The fact line must say so (200k context (built-in)) instead of showing a confidently wrong number.
  • Ambiguity. deepseek-flash exists under several providers. A bare model name needs a ranked match, and the fact line must name the provider it picked.
  • Upstream trust. A wrong limit.context silently moves the compaction point. A typed override must always win.
