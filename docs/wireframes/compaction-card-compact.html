Compaction card, made compact

The “Conversation Compaction” card is 1,140 px of transcript that says “50 messages were rolled up”. Planning for a smaller card, and the fix for the message that never appears under it.

Wireframe for task_1794761808908_1 · the transcript surface is ChatMessageRow.vue + CompactionCard.vue · dark theme, Kanagawa Dragon tokens (the surface keeps the app’s own borders, code faces and badges — it is an app screen, not a landing page).

The bug, from the real database

session task_1794721542834_8 · read straight out of agent.db

The compaction envelope is written to llm_history as a role=user row, so the message you send straight after it is the next user row. The transcript groups consecutive same-role rows into one block, and that block draws the card instead of its messages.

why One block, one renderer. messageGroups merges the two user rows; ChatMessageRow then checks isCompactionMessage(group.messages[0]) — true — and draws the card inside a v-if, with every other message of the block in the v-else. Your message is in the DOM’s data and in the model’s context, and on no pixel of the screen. The same merge is why the turn gets no jump-pill on the right rail.

## Goal
Give glinlandui an adb-style control surface for *running* Zig apps: the app hosts a devtool
service; `glinlandui-inspect` attaches by name and issues `tree`, `json`, `pick`, `do <action>`,
`quit` — the same actions the headless CLI performs. **Done and verified live.**

## Constraints & Decisions
- Transport is a **unix socket** (`$XDG_RUNTIME_DIR/glinlandui-<name>.sock`, else `/tmp`) plus a
  **pipe** — not a TCP port: per-user, no port allocation, and one wake fd the window can poll.
- The service is only up when the app asks: `serve()` returns null unless `GLIN_DEVTOOLS=1`.
- Requests are served **in the frame loop**: begin → fires a waiting action before the click
  registry is cleared, `end` serialises the reply after `resolve`. The socket thread only moves
  bytes.
- `src/core/**` stays OS-blind: the transport is a platform seam beside `clipboard` / `open`.
- Removing the blocking `wl_display_dispatch` was required for waking an idle app.

## Steps
- [x] 1. `core/devtools/service.zig`: `tree` / `json` / `pick` / `do` / `quit`, per-frame state
  machine, atomic request/reply slots. Tests in-process. Commit `4a50ecf`.
- [x] 2. `cli.performOn(host, action, arg)` + `cli.targetOf` shared by `--do` and the service.
- [ ] 3. `inspect tree` prints the clay node tree with stable paths.
