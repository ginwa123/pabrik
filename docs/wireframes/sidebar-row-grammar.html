After: one grammar for every line in the panel

One mark column and one label column, for the whole panel. Every row puts its label at 28 and keeps the 16px slot at the gutter for at most one mark: a disclosure chevron, a branch badge, a status glyph, or nothing at all. The projects list has no indent of its own, so nothing opens an empty strip beside the gutter. Only a third level, a task under a project, takes one step more, at 44.

Everything the row knows, in one right-aligned group

The mark column is on the left, one slot for one mark, and the trailing group is right-aligned in a fixed order: status mark, then time. The branch badge leaves the label for the mark column, so a chat with a pull request keeps the same label edge as one without. The status mark keeps its meaning and loses its roam. The time is always text-micro and tabular, so the column right of the label is one width no matter what the row has to say.

One time treatment

Idle shows a bare duration at 70% in --semantic-text-dim. Running shows the same bare duration at full opacity in --color-yellow, with seconds. Stale shows the same value in --color-orange. Colour and precision carry the state, so the slot keeps one weight and the pill stops competing with the pulsing orange dot, which is the app's only other filled mark.

One selected row

--semantic-active-bg on --semantic-active-text with a 2px inset violet bar, on every kind of row. The hardcoded pair goes.

One set of columns

Two columns, and one step. The mark column is 16px at the gutter, so it runs 12 to 28 and every label in the panel starts at 28: a section title, a chat, a document, a project. That is what makes the panel read as one list rather than as four lists that happen to share an edge. The indent step stays for a third level, a task under an expanded project, and it is applied to the row itself rather than to a wrapper, so the mark column sits at 28 and the task's label at 44. There is no vertical rule anywhere in the panel: a line down the left of a list is the hairline divider the app's house style bans, and the label column plus the row order already carry the nesting without it.

Decisions a reviewer can flip

The projects list is flat: no per-depth indent for a project, and one label edge at 28.
The first cut indented the projects list by a step and a rail, which put the project chevron at 28 and the name at 44 and opened a 24px empty strip down the left of the tree. That strip reads as a broken column, not as nesting, so the indent is gone: a project row now looks like a section row, chevron in the mark column and name at 28, and the nesting is carried by order and by the header it sits under. The cost is 16px of label width on the chat and document rows, which started at 12. Flip this back if nesting needs a visible step more than one label edge is worth.
The branch badge goes in the mark column, not the trailing group.
Once the mark column exists, the badge belongs there: it is the row's one mark and the column is what stops it from moving the label. Putting it in the trailing group instead would leave the mark column to the chevrons alone and let the chat and document labels sit at 12, which spends 16px less on a mark column most chat rows do not use, at the price of two label edges in the panel instead of one.
New Chat stays 40px but takes the shared columns.
Shrinking it to the 32px row would make it recede, and it is the one action that always works. It keeps its height and its bare-text treatment, and puts its glyph at 12 and its label at 28, so the left rail runs unbroken from the header to the last document.
The running indicator keeps the words and moves beside the action.
A dot alone would be shorter, but the number of running workers is information. It moves out of the count position, where it read as part of the project total, into the trailing group beside the plus.

Where the fix should be guarded

Sidebar.spacing.spec.ts is a source scanner: it reads class strings and asserts that they contain a token. That is why it missed all of this. It cannot see nesting, it cannot see that two files hardcode two different greys, and it never looked at Pinned at all.

A rendered assertion would have caught every finding above. Mount the sidebar against a fixture with one pinned chat, one running chat, one chat with a branch, one project with a task and one document, then assert observable geometry: every row's height equals the row token, every label's left offset is one of the three documented columns, every header's count and action are present and aligned, no button contains a button, and a selected chat row and a selected project row share one background. That is a behaviour test of the contract rather than a grep of its spelling: it stays green through a rename or a class reshuffle, and goes red the moment a row drifts.
